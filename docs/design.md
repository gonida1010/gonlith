## 1. 한 줄 정의

**Gonlith는 어떤 AI를 쓰든 같은 기억과 지식을 쓰게 해 주는, 내 컴퓨터 안의 기억·지식 저장소다. 설치는 한 줄, 관리는 화면에서 클릭으로 한다.**

세 기둥:
1. **AI 공용 기억** — Claude·Gemini·Cursor·로컬 모델 등 어떤 MCP 클라이언트에 연결해도 같은 기억을 쓴다. "내 선호", "이 프로젝트의 결정 사항"을 AI마다 다시 설명하지 않는다.
2. **나만의 지식 저장소** — 노트·문서·PDF·웹페이지·폴더를 넣으면 자동으로 읽고 색인한다. AI가 내 자료를 근거로 답한다.
3. **정말 쉬운 관리** — 무엇이 저장됐는지 보고, 고치고, 지우고, 중복을 합치고, 잘못된 것을 되돌리는 일을 화면에서 한다. 정리는 사람·로컬 AI·연결된 AI 중 원하는 쪽에 맡긴다.

바탕에 깔린 것(사용자 행동 없음): 모든 변경은 이력으로 남아 되돌릴 수 있고, 저장소가 밖에서 조작되면 경고한다.

## 2. 왜 필요한가

| 문제 | 지금 | Gonlith 이후 | 측정 (§17) |
| :--- | :--- | :--- | :--- |
| 기억 단절 | AI 제품마다 기억이 따로 있고, 바꾸면 처음부터 다시 설명한다 | 한 저장소를 모든 클라이언트가 공유 | 클라이언트별 연결 성공, 교차 검색 |
| 흩어진 자료 | 노트·PDF·북마크가 여기저기 있어 AI에 매번 붙여 넣는다 | 넣어 두면 AI가 찾아 쓴다 | 형식별 수집 성공률, 문서 질의 Recall@k |
| 블랙박스 기억 | AI가 나에 대해 무엇을 저장했는지 보기·고치기 어렵다 | 화면에서 전부 보고 고친다 | 관리 작업 단계 수 |
| 쌓이는 쓰레기 | 중복·모순·오래된 기억이 쌓여 답이 흐려진다 | 정리 제안 + 자동 정리(선택) + 되돌리기 | 제안 정밀도·재현율, 되돌리기 성공 |
| 설치 난도 | JSON 설정 편집·Docker·API 키 | 명령 1줄 + 화면 안내, 자동 연결 | 설치→첫 검색 단계 수, 수동 편집 파일 수 |
| 한국어 | 영어 기본값. SQLite FTS5 trigram은 2글자 한국어 단어를 못 찾는다 (확인, `docs/research.md` §4) | 측정으로 고른 한국어 기본값 | 한국어 평가셋 Recall@k |

**비목표:**
* 클라우드 호스팅·계정·다중 사용자 서버는 첫 범위가 아니다. 기기 간 동기화는 나중에 검토한다.
* 대화 자동 녹화는 하지 않는다. MCP 서버는 대화를 볼 수 없다. AI가 저장하거나 사용자가 넣은 것만 다룬다.
* 추론 엔진(Ollama·vLLM)과 MCP로 직접 연결하지 않는다. 그것들은 MCP 클라이언트가 아니다. 로컬 모델은 MCP를 지원하는 호스트 앱을 거쳐 쓰거나, 정리 담당 AI로 쓴다(§10).

## 3. 경쟁과 차별점

상세 비교는 `docs/research.md` §7 (2026-11-21 조사).

**가장 가까운 경쟁자:** Hindsight (MIT, 1.2.3, 2026-11-19). 관리 화면이 가장 풍부하고(편집·무효화·이력·감사·내보내기), 파일 업로드와 Obsidian 단방향 감시가 있다. 확인. 다만 Docker나 LLM 키로 설치하고, 정리는 LLM이 배경에서 자동으로 하며 사람 확인 단계를 찾지 못했다 (추정).

**비어 있는 자리 → Gonlith가 채울 것:**

| 빈 곳 | 근거 | Gonlith |
| :--- | :--- | :--- |
| 일반인 설치 | 조사한 MCP 저장소 모두 pip·uv·npm·Docker 설치와 클라이언트 JSON 직접 편집이 필요하다 (확인) | 명령 1줄 + 클라이언트 자동 탐지·연결 (§11.4) |
| 로컬 "MCP + 관리 화면" | mem0 OpenMemory가 2026-07-29 저장소에서 제거되었고, mem0 MCP는 클라우드 전용이다 (확인) | 로컬 관리 화면 (§12) |
| 정리를 누가 할지 고르기 | Hindsight는 자동 병합, Cognee는 충돌 표시만, mcp-memory-service는 규칙 기반 대체. 사람 확인 큐나 처리자 선택은 찾지 못함 (추정) | 사람 / 로컬 AI / 연결된 AI 선택 + 제안·자동 선택 (§10) |
| 사용자용 되돌리기 | 이력은 API·git 수준이다. 화면의 "이 변경 되돌리기"는 무료 로컬판에서 찾지 못함 (추정). basic-memory 스냅샷은 유료 클라우드만 (확인) | 모든 변경 되돌리기, 자동 정리 일괄 되돌리기 (§13) |
| 파일 + 웹 주소 + 감시 폴더 한 번에 | basic-memory는 Markdown만, Hindsight는 URL 수집이 없음, Cognee는 감시 미확인, mcp-memory-service는 업로드만 (확인) | §8 |
| 한국어 기본값 | 대부분 영어 기본 임베딩·토크나이저. 한국어는 선택 설정 수준(Hindsight Lindera) (확인) | 측정으로 정한 한국어 기본값 (§9) |
| 라이선스 | basic-memory·Khoj는 AGPL (확인) | Apache-2.0 |

**하지 않는 경쟁:** 지식 그래프 추출 품질(Cognee·Graphiti), 에이전트 자기 기억 재작성(Letta)은 겨루지 않는다. Gonlith는 "쉽게 넣고, 어디서나 찾고, 쉽게 고치고 정리하는 저장소"에 집중한다.

## 4. 사용자와 사용 장면

| 사용자 | 상황 | Gonlith에서 하는 일 |
| :--- | :--- | :--- |
| 일반인 | Claude Desktop·ChatGPT 계열 앱을 번갈아 쓴다. 개발 지식 없음 | 설치 1줄 → 화면 안내 → "Claude에 연결" 클릭. 이후 "나 채식해"라고 한 번 말하면 어느 AI든 기억한다. 화면에서 "AI가 아는 나"를 보고 고친다 |
| 바이브 코더·개발자 | Claude Code·Cursor·Gemini CLI를 섞어 쓴다 | 프로젝트별 공간이 자동으로 생긴다. 결정 사항·규칙이 도구를 바꿔도 이어진다 |
| 자료 모으는 사람 | PDF 논문·웹 기사·Obsidian 노트 | 폴더를 지정하면 자동 색인된다. "지난달 읽은 RAG 논문에서 평가 방법이 뭐였지?"를 아무 AI에게나 묻는다 |
| 정리하기 싫은 사람 | 기억이 쌓여 엉망이 된다 | 정리를 "로컬 AI 자동"이나 "연결된 AI"로 설정한다. 바뀐 것은 이력에서 한 번에 되돌린다 |

**대표 흐름 (일반인, 목표: 5분 안에 첫 사용):**
1. 안내 페이지의 명령 한 줄을 붙여 넣는다(§11.4).
2. 브라우저 화면이 자동으로 열린다. 설치된 AI 앱이 목록에 나오면 체크하고 "연결"을 누른다.
3. AI 앱을 다시 켜고 "내가 좋아하는 커피 기억해"라고 말한다.
4. 다른 AI 앱에서 "내 커피 취향 알아?"라고 묻는다 → 답한다.
5. 화면 "AI가 아는 나"에 그 기억이 보인다. 출처는 "Claude Desktop, 11월 21일"이다.

## 5. 설계 원칙

1. **설정 0개로 동작한다.** 첫 실행에 저장소가 자동으로 만들어진다. 키·암호·승인 절차는 기본 흐름에 없다.
2. **사용자에게 보안 행동을 요구하지 않는다.** 안전장치(§14)는 보이지 않게 동작한다. 보호 모드는 원하는 사람만 켠다.
3. **자동으로 바뀌는 것은 모두 되돌릴 수 있다.** AI가 쓰든, 자동 정리가 합치든, 이력에 남고 한 번에 되돌린다. 자동 정리를 안심하고 맡길 수 있게 하는 장치다.
4. **로컬·오프라인 기본.** 계정·API 키·텔레메트리가 없다. 네트워크는 사용자가 넣은 웹 주소 수집, 사용자가 켠 모델 내려받기에만 쓴다.
5. **어떤 MCP 클라이언트든.** 특정 제품에 묶이지 않는다. 클라이언트마다 다른 지원 범위는 호환표로 공개한다.
6. **기본값은 측정으로 정한다.** 검색 방식, 조각 크기, 중복 기준 같은 값은 우리 데이터로 측정해 정하고, 설정 파일에 출처와 함께 둔다(AGENTS.md).

## 6. 전체 구조

```
 MCP 클라이언트들 (Claude Code · Claude Desktop · Cursor · VS Code · Gemini CLI · LM Studio …)
        │ stdio (기본) / Streamable HTTP (선택)
        ▼
 ┌──────────────────────────── gonlith ─────────────────────────────┐
 │ MCP 계층    remember · search · forget · ingest · (organize)         │
 │ 수집기      파일·웹·폴더 → Markdown 변환 → 조각 → 색인 (§8)           │
 │ 정리기      중복·충돌·오래됨·분류 제안 → 사람 / 로컬 AI / 연결된 AI (§10) │
 │ 검색        한국어 어휘 색인 + 선택적 벡터, 출처·공간 필터 (§9)        │
 │ 기록 계층   추가 전용 이력 로그 · 무결성 확인 · 되돌리기 (§13)          │
 │ 저장        SQLite 1개 파일 + 원본 파일 폴더                         │
 └──────────────────────────────────────────────────────────────────┘
        ▲                         ▲                         ▲
   관리 화면 (localhost)        CLI (gonlith …)          로컬 AI (선택)
                                                        OpenAI 호환 주소, 예: Ollama
```

* **하나의 저장소, 여러 클라이언트:** 클라이언트마다 서버 프로세스가 떠도 같은 데이터 폴더를 쓴다. 확인: 16개 프로세스 동시 쓰기에서 유실 0 (`docs/measurements/s1-record-layer.md` §4).
* **백그라운드 작업**(폴더 감시·수집·정리)은 한 프로세스만 맡는다. 데이터 폴더 잠금 파일로 담당을 정하고, 담당이 사라지면 다른 프로세스가 이어받는다. 같은 일이 중복 실행되지 않게 하기 위함이다 (판단, S6에서 시험).
* **데이터 폴더:** OS 표준 위치(`platformdirs`). `GONLITH_HOME`으로 바꿀 수 있다. iCloud·Dropbox 같은 동기화 폴더 안이면 경고한다(SQLite WAL 손상 위험).

## 7. 데이터 모델

### 7.1 항목 종류

| 종류 | 무엇 | 예 | 누가 만듦 |
| :--- | :--- | :--- | :--- |
| `memory` | 짧은 기억 (한두 문장) | "사용자는 채식한다", "이 프로젝트는 uv를 쓴다" | AI(`remember`), 사람(화면) |
| `note` | 사람이 쓰는 Markdown 노트 | 회의 메모, 할 일 | 사람(화면), AI |
| `document` | 수집된 자료 (원본 + 추출한 Markdown) | PDF, 웹 기사, docx, 폴더 속 파일 | 수집기 |

* `document`는 검색용 **조각**으로 나뉜다. 조각은 파생 색인이다. 원본·추출본에서 언제든 다시 만들 수 있으므로 이력 로그에 넣지 않는다.

### 7.2 공통 속성

| 속성 | 뜻 |
| :--- | :--- |
| `space` | 공간 (예: `나`, 프로젝트 이름). 클라이언트 설정이나 도구 인자로 정한다. 기본 공간 이름은 설정 파일에 |
| `tags` | 태그 목록 |
| `category` | 기억 분류 (`preference`·`fact`·`person`·`project`·`procedure`·`event` 등, 목록은 설정 파일) |
| 출처 | 누가 만들었나(`human` / 클라이언트 이름 / `local_ai:<모델>`), 어디서 왔나(대화·파일 경로·URL), 언제 |
| `origin` | `own` (사람·AI가 직접 쓴 것) / `external` (파일·웹·도구 출력에서 온 것) — 안전장치용(§14) |
| 유효 시간 | `valid_from`·`valid_to` (선택): "2026-03부터 부산에 산다" |
| 상태 | `active` / `archived`(보관, 검색 기본 제외) / `deleted`(내용 삭제됨) |
| 버전 | 고칠 때마다 새 버전. 옛 버전은 이력에 남는다 |
| `pinned` | "중요" 표시. 검색 순위를 올리고 자동 정리 대상에서 뺀다 |

### 7.3 고치기·지우기 (사용자에게는 평범하게, 안쪽은 이력으로)

* **고치기:** 화면에서 바로 편집한다. 안쪽에서는 `revise` 기록이 새 버전을 만든다. 옛 버전은 이력에서 볼 수 있고 되돌릴 수 있다.
* **지우기:** 두 단계다.
  * 휴지통(`archive`): 언제든 복구할 수 있다.
  * 완전 삭제(`delete`): 내용을 실제로 지운다. 이력에는 "지워짐"만 남는다(§13.3).
  * AI의 `forget`은 휴지통으로만 보낸다. 완전 삭제는 화면·CLI에서 사람이 한다. AI 실수로 사라지는 일이 없게 하기 위함이다.
* **합치기:** 여러 항목을 하나로 합친다. 원래 항목들은 "합쳐짐"으로 보관되고 되돌릴 수 있다.

### 7.4 Markdown 거울 폴더 (확정, `docs/decisions.md` D11)

* **목적:** 사람이 Obsidian·편집기로 열어 보고, 파일 접근 권한이 있는 AI(Claude Code·Codex 등)가 MCP를 거치지 않고도 읽어 확인할 수 있게 한다.
* **원칙:**
  * 정본은 저장소(SQLite)다. 거울은 저장소가 바뀔 때마다 자동으로 다시 만드는 단방향 사본이다.
  * 거울 파일을 고쳐도 저장소에 반영되지 않는다.
    * 파일마다 맨 위에 "자동 생성, 고치려면 Gonlith 화면에서"라는 안내를 넣는다.
    * 사용자가 고친 흔적이 보이면 덮어쓰기 전에 그 파일을 수집함에 따로 보관한다.
  * 양방향 동기화는 충돌 처리가 복잡해 첫 범위에서 뺀다.
* **배치:**
  * 공간별 폴더.
  * 기억은 공간·분류별로 한 파일에 모은다. 예: `나/선호.md`.
  * 노트·문서는 항목 하나가 파일 하나다.
  * 파일 머리(front matter)에 항목 번호, 출처, 수정 시각, `origin`을 적는다.
* **위치:** 기본은 데이터 폴더 안 `mirror/`이고 설정으로 바꿀 수 있다.
  * 감시 폴더로 거울을 다시 수집하는 순환은 경로 비교로 막는다.
  * `hidden` 공간은 거울에 쓰지 않는다(§11.3).
* **검색 색인과 별개:** 청킹·임베딩은 저장소 내용으로 따로 만드는 검색용 색인이다(§9). 거울과 서로 의존하지 않는다.
* **휴지통·완전 삭제:** 거울에서도 사라진다.

## 8. 수집 (지식 저장소)

### 8.1 넣는 방법

| 방법 | 누가 | 비고 |
| :--- | :--- | :--- |
| 화면에 끌어다 놓기·파일 선택 | 사람 | 가장 쉬운 길 |
| 웹 주소 붙여 넣기 | 사람 | 본문만 추출 |
| 감시 폴더 등록 (예: Obsidian 보관함, 다운로드 폴더의 `논문/`) | 사람 | 새 파일·변경 자동 반영 (§8.4) |
| `gonlith add <경로|URL>` | 사람(CLI) | |
| MCP `ingest` 도구 | AI | "이 링크 저장해 둬" |
| 녹음 파일 (휴대폰 음성 메모, 회의 녹음) | 사람 | 로컬 음성 인식으로 대본 생성 (§8.5) |
| 대본·대화 내보내기 파일 (.txt·.srt·.vtt·AI 대화 내보내기) | 사람 | 대화 정리 대상 (§8.5) |

### 8.2 처리 과정

```
원본 받기 → 형식 판별 → Markdown 추출 → 조각 나누기 → 색인(어휘, 선택적 벡터) → 중복 확인 → 검색 가능
```

* **원본 보관:** 끌어다 놓기·업로드한 파일은 데이터 폴더에 복사한다. 원본이 지워져도 남게 하기 위함이며, 내용 해시로 이름을 붙여 같은 파일을 두 번 저장하지 않는다. 감시 폴더는 복사하지 않고 경로·해시만 기록한다. 보관함을 통째로 중복 저장하지 않기 위함이다.
* **변환기 (후보, 라이선스 확인 완료, `docs/research.md` §8):**

| 형식 | 기본 변환기 | 선택 (무거움) |
| :--- | :--- | :--- |
| Markdown·텍스트 | 그대로 | — |
| PDF (텍스트 있음) | `pypdf` 또는 `markitdown` — S5 측정으로 결정 | `docling` (표·레이아웃·스캔 OCR) |
| Word·PowerPoint·Excel | `markitdown` | `docling` |
| HTML·웹 주소 | `trafilatura` (본문 추출) | — |
| 이미지·스캔 PDF | — (S5 이후) | `docling` OCR |

  * AGPL·GPL 라이브러리(`pymupdf`, `html2text`)는 쓰지 않는다. Apache-2.0 배포와 맞지 않기 때문이다.
  * 무거운 변환기는 사용자가 켤 때만 설치한다(선택 의존성 묶음).
* **조각 나누기:** Markdown 제목 구조를 따라 나눈다. 조각 크기는 검색 측정(S5·S7)과 임베딩 모델의 입력 한도로 정한다.
* **기록:** `document` 항목에 원본 출처, 형식, 제목, 원본 해시, 추출본 해시, 변환기 이름·버전, 수집 시각을 남긴다. 변환기를 바꿔 다시 추출하면 새 버전이 된다.
* **실패:** 실패한 파일은 화면 "수집 문제" 목록에 이유와 함께 보인다. 거기서 다시 시도하거나 무거운 변환기로 시도한다.

### 8.3 웹 수집

* `http`·`https`만 받는다. 사설·루프백·링크 로컬 주소는 기본 차단한다. AI가 `ingest`로 내부망을 찌르는 것(SSRF)을 막기 위함이며, MCP 보안 모범 사례가 다루는 위험이다 (확인, `docs/research.md` §2.4).
* 크기 상한·시간 제한은 설정값이다.
* 로그인이 필요한 페이지는 첫 범위가 아니다. 그런 페이지는 브라우저에서 저장한 파일을 넣는다.

### 8.4 감시 폴더

* 파일 추가·변경·삭제를 감지해 반영한다. 감시는 `watchfiles`로 한다. 원본 삭제는 휴지통으로 처리한다.
* 포함·제외 규칙(확장자, `.git` 같은 폴더)은 폴더별 설정이다.
* 처음 등록할 때 파일 수와 예상 시간을 보여 주고 시작한다.

### 8.5 음성과 대화 기록

사람들이 AI와 음성으로 대화하고 회의를 녹음하는 일이 많아졌다. 그래서 음성과 대화 기록도 기억·지식으로 들어올 수 있어야 한다. 근거는 `docs/research.md` §10.

**들어오는 길 (현실적인 순서):**

| 길 | 방식 | 이유 |
| :--- | :--- | :--- |
| 1. 녹음 파일 | 끌어다 놓기·감시 폴더 → 로컬 음성 인식 → 대본 | 가장 흔한 경우. 네트워크·계정 없이 처리 |
| 2. 대본·대화 내보내기 | .txt·.srt·.vtt, AI 앱 대화 내보내기 파일 | 이미 글로 된 대화. 음성 인식이 필요 없음 |
| 3. 음성 모드 AI | 음성 대화 중 AI가 텍스트로 `remember` 호출 | MCP 규격에서 도구 입력에는 음성 형식이 없다 (확인). 실시간 음성 연결은 만들지 않는다 |

**처리 과정 (녹음 파일):**
```
음성 → 음성 구간 검출 → 음성 인식(대본) → 화자 구분(선택) → document(대본) 저장 → 대화 정리 제안(§10.1)
```
* 음성 구간 검출은 silero-vad(MIT)로 한다. 화자 구분은 sherpa-onnx(Apache-2.0, 토큰 불필요)로 한다.
* 음성 인식 기본 후보는 whisper-large-v3-turbo + whisper.cpp(MIT)다. 비교 후보 Qwen3-ASR(Apache-2.0)과 함께 한국어 낭독·대화 음성으로 측정한 뒤 정한다. 두 모델 모두 한국어 공식 수치가 없다.
* 음성 기능은 선택 설치(`gonlith[voice]`)다. 모델은 사용자가 켤 때 내려받는다.
* 대본은 `document`로 저장하고 원본 음성 출처·시각·화자 정보를 남긴다.
* 원본 음성 파일은 기본으로 보관하지 않고 사용자가 고른다. 용량이 크고 다른 사람 목소리가 들어 있어서다.
* 다른 사람이 녹음된 파일은 가져오기 화면에서 "녹음 대상의 동의"를 한 번 안내한다.

**대화 정리:** 대본은 길고 잡담이 많다. 그래서 정리기(§10)가 대본에서 아래 후보를 뽑아 제안한다. 처리자(사람·로컬 AI·연결된 AI)와 적용 방식은 다른 정리 제안과 같은 설정을 따른다.
* 요약
* 사실·선호·결정
* 할 일

## 9. 검색

* **하나의 검색이 기억·노트·문서 조각을 함께 찾는다.** 종류·공간·태그·기간으로 거를 수 있다.
* **결과마다 함께 돌려주는 것:**
  * 내용(조각이면 앞뒤 맥락 포함)
  * 출처: 문서 제목·위치, 누가 언제 저장했는지
  * 일치 이유
  * `origin` 꼬리표
* **1단계 (기본, 내려받기 없음): 한글 문자 2-gram + 영숫자 단어를 SQLite FTS5(BM25)로 색인한다.** 확인 (`docs/measurements/s2-mcp-core.md` §1):
  * R@5 0.942로, FTS5 trigram 0.575·기본 단어 분할 0.583 대비 크게 높다.
  * kiwi 형태소(0.958)는 선택 설치(`gonlith[korean]`)로 둔다. 이득은 질의 1개인데 설치가 126 MB 늘고 첫 로딩이 0.8초 걸린다.
  * 남은 오답은 동의어·한영 교차라 2단계에서 다룬다.
* **2단계 (선택, 켜면 내려받음):** 임베딩 벡터와 1단계 점수를 결합한다.
  * 실행: ONNX 계열(`fastembed`·`model2vec`)을 PyTorch 계열보다 먼저 측정한다. 설치가 가볍기 때문이다.
  * 저장: `sqlite-vec` 또는 메모리 내 전수 비교.
  * 모델: 설정 파일로 고르며, 한국어 성능을 측정해 기본값을 정한다.
* **순위 보정:** `pinned`는 올리고, 오래된 것·보관된 것은 내린다. 보정 가중치는 설정값이며 측정으로 정한다.
* **시점 검색:** `as_of` — 그 시점에 유효했던 기억만 찾는다(유효 시간 기준).
* **평가셋:** 회사 데이터 없이 직접 만든 한국어·영어 기억 질의 + 공개 문서 질의. 표본은 시드를 고정한다.

## 10. 정리 (중복·충돌·오래됨·분류)

### 10.1 정리기가 찾는 것

| 제안 종류 | 찾는 방법 | 해결 선택지 |
| :--- | :--- | :--- |
| 완전 중복 | 정규화한 내용 해시가 같음 | 하나로 합치기 |
| 거의 중복 | 유사도 기준 이상 (기준은 S8 측정) | 합치기 / 둘 다 두기 |
| 충돌 | 같은 대상에 다른 사실 ("서울에 산다" vs "부산에 산다") | 최신 것만 / 기간으로 나눠 둘 다(유효 시간) / 합치기 |
| 오래됨 | 유효 기간 끝남, 오랫동안 검색되지 않음 (기간은 설정값) | 보관 / 그대로 |
| 미분류 | 공간·태그 없음 | 제안된 공간·태그 적용 |
| 대화 정리 | 새 대본·대화 기록 (§8.5) | 요약 노트 저장 / 사실·선호·결정을 기억으로 저장 / 할 일 추출 / 그대로 |
| 수집 문제 | §8.2 실패 | 다시 시도 / 무거운 변환기 |

### 10.2 누가 해결하나 — 설정으로 고른다

제안 종류마다 두 가지를 고른다.

| 설정 | 값 | 뜻 |
| :--- | :--- | :--- |
| 처리자 | `human` | 화면 "정리함"에 모아 보여 주고 사람이 클릭으로 해결 |
| | `local_ai` | 설정된 로컬 모델(OpenAI 호환 주소, 예: Ollama)이 판단 |
| | `connected_ai` | 연결된 AI가 MCP `organize` 도구로 목록을 받아 판단 ("내 기억 정리해줘") |
| 적용 | `suggest` | 처리자(AI)가 해결안을 내면 사람이 한 번에 확인·적용 |
| | `auto` | 처리자가 바로 적용 |

* **기본값 (확정, `docs/decisions.md` D10):**
  * 완전 중복: `auto` (되돌릴 수 있음)
  * 나머지: `human` + `suggest`
  * AI 처리자는 사용자가 모델이나 연결된 AI를 고를 때 켜진다
* **안전망:**
  * 자동 적용된 변경은 모두 처리자 이름과 함께 이력에 남는다.
  * 화면의 "자동 정리 기록"에서 한 번에 되돌린다. 정리 실행 단위로 묶어 되돌릴 수 있다.
  * `pinned` 항목은 자동 정리하지 않는다.
* **로컬 AI 설정:** 주소, 모델 이름, 프롬프트 틀은 모두 설정 파일에 둔다(AGENTS.md 하드코딩 금지). 화면은 실행 중인 Ollama를 찾아 설치된 모델 목록을 보여 주고 고르게 한다.
* **외부 내용 주의:** 수집 문서 속 문장이 정리 AI에게 지시하지 못하게, 판단 입력의 외부 내용은 데이터 구획(§14.2)으로 감싼다. 정리 AI에는 도구 권한을 주지 않고, 정해진 해결 선택지 중 하나만 고르게 한다 (판단).
* MCP Sampling(서버가 클라이언트 모델을 빌려 쓰는 기능)은 2026-07-28 규격에서 폐지 예정이라 쓰지 않는다 (확인, `docs/research.md` §2.4). 그래서 `connected_ai`는 도구 방식이다.

## 11. MCP 연결

### 11.1 도구 (적게, 쉽게)

| 도구 | 하는 일 | 주요 입력 |
| :--- | :--- | :--- |
| `remember` | 기억 저장 (같은 내용이 있으면 새로 만들지 않고 알려 줌) | `content`, `category?`, `space?`, `tags?`, `valid_from?`, `valid_to?`, `replaces?` |
| `search` | 기억·노트·문서 검색 | `query`, `space?`, `kinds?`, `as_of?`, `limit?` |
| `forget` | 휴지통으로 | `id`, `reason?` |
| `ingest` | 파일 경로·웹 주소 수집 (오래 걸리면 작업 번호 반환) | `source`, `space?`, `tags?` |
| `organize` | 정리 제안 목록·해결. `connected_ai` 처리자가 켜졌을 때만 노출 | `action`, `suggestion_id?`, `resolution?` |

* 도구 설명문은 짧게 고정한다. 클라이언트 컨텍스트를 매번 차지하기 때문이다. 문구는 설정 파일에 둔다.
* **결과는 텍스트 블록에도 같은 내용을 넣는다.** `structuredContent`를 무시하는 클라이언트가 있기 때문이다 (클라이언트별 확인 V4).
* **서버 `instructions`:** 언제 기억하고 언제 검색하는지 짧게 안내한다. 예: "사용자가 선호·사실을 말하면 `remember`, 답하기 전에 관련 기억을 `search`".
* **MCP 프롬프트:** "이번 대화에서 배운 것 저장", "내 기억 정리". 이를 지원하는 클라이언트에서는 슬래시 명령처럼 보인다(지원 범위 V13).
* **출력 크기:** 텍스트 결과는 설정한 글자 수 예산(기본 5만 자, Claude Code가 파일로 빼는 기준) 안에서 자르고, 잘린 개수를 알린다.
* **스레드:** SDK는 동기 도구를 작업 스레드에서 실행한다. SQLite 연결은 스레드에 묶이므로 처리 함수는 비동기로 두고 이벤트 루프 한 곳에서 직렬 실행한다.
* **규격:** 공식 `mcp` SDK 2.x를 쓴다. 2026-07-28(무상태) 규격과 2025-11-25 클라이언트를 모두 지원한다고 밝힌다 (확인, `docs/research.md` §2.4).

### 11.2 공간 자동 결정

* 우선순위:
  1. 도구 인자 `space`
  2. 클라이언트 설정의 환경변수 `GONLITH_SPACE`
  3. 기본 공간
* `setup`이 프로젝트 폴더 단위 설정(예: Claude Code `.mcp.json`)을 만들 때 폴더 이름으로 공간을 채운다. MCP Roots는 폐지 예정이라 쓰지 않는다 (확인).
* 검색은 기본적으로 현재 공간 + `나`(개인) 공간을 함께 본다. 범위는 설정값이다.

### 11.3 공간 공개 범위 (개인 기억 보호, 쉬운 방식)

| 공개 범위 | 뜻 |
| :--- | :--- |
| `all` (기본) | 모든 연결된 AI가 검색 |
| `local_only` | 로컬 모델 클라이언트로 표시된 곳에만 |
| `hidden` | AI 검색에서 제외. 화면에서만 보임 |

* 클라이언트의 로컬·외부 구분은 `setup`이 알려진 클라이언트 목록(설정 데이터 파일)으로 채우고, 사용자가 바꿀 수 있다.
* 클라이언트가 밝힌 이름을 믿는 방식이라 강한 격리는 아니다. 이 점을 화면에 적는다.

### 11.4 설치와 연결 — 걸림 없이

| 단계 | 일반인 | 개발자 |
| :--- | :--- | :--- |
| 설치 | 안내 페이지의 명령 1줄(`uv` 기반 설치 스크립트) 또는 Claude Desktop 확장 묶음(MCPB, V5) | `uvx gonlith` / `uv tool install gonlith` |
| 첫 실행 | `gonlith` → 저장소 자동 생성 → 브라우저 화면 | `gonlith setup --no-browser` |
| 연결 | 설치된 MCP 클라이언트 자동 탐지 → 체크 → 설정 파일 백업 후 추가, 미리 보기 | `gonlith setup --client <이름>` 또는 설정 조각 출력 |
| 가져오기 | 기존 기억 파일(CLAUDE.md, 공식 memory 서버 JSONL 등)을 찾으면 가져올지 묻기 | `gonlith import` |
| 확인 | "연결 시험" 버튼 | `gonlith doctor` |

**걸림을 없애는 규칙:**
* 서버 시작이 빨라야 한다. 무거운 모듈(임베딩·변환기)은 처음 쓸 때 불러온다. 시작 시간을 측정 항목으로 둔다.
* 클라이언트 설정에는 실행 파일을 절대 경로로 적는다. 클라이언트마다 다른 `PATH`를 피하기 위함이다.
* `stdout`에는 MCP 메시지만 쓴다. 로그는 파일과 `stderr`로 보낸다.
* 아래 정보는 자주 바뀌므로 코드가 아니라 **설정 데이터 파일**에 둔다. 출처 링크와 확인 날짜를 붙인다:
  * 클라이언트별 설정 파일 위치·형식
  * 로컬·외부 구분
* 클라이언트별 호환표를 공개한다. 항목은 연결, 구조화 출력, 프롬프트, 이미지 반환이다. "완벽 호환"이라고 쓰지 않는다.

## 13. 기록 계층 (이력·되돌리기·무결성)

S1에서 구현·측정한 계층이다 (`docs/format.md`, `docs/measurements/s1-record-layer.md`). 사용자에게는 **"변경 이력과 되돌리기"**로만 보인다.

### 13.1 구조

* 모든 변경은 추가 전용 로그의 한 항목이다. 항목 종류는 `genesis`, 항목 생성, `revise`, `archive`, `delete`, 합치기, 태그·공간 변경 등이다.
* 각 항목은 정해진 바이트 형식으로 저장한다(DSSE PAE 봉투, 정규 JSON, 엄격 판독). 이 바이트로 RFC 6962 Merkle 트리를 만든다. 확인: 공인 시험 벡터 통과.
* 내용은 로그와 분리된 표에 `SHA-256(salt ‖ 내용)`과 함께 둔다. 그래서 내용을 실제로 지워도 나머지 이력의 검증은 유지된다.
* 서버 시작 때 로그를 재생해 현재 상태를 만든다. 그 뒤로는 새 항목만 이어서 재생한다. 확인: 10만 건 1.07초, 증분 100건 1.1ms.

### 13.2 이것이 사용자에게 주는 것

* **버전 이력:** 항목마다 누가 언제 무엇을 바꿨는지 보인다.
* **되돌리기:** 한 항목, 또는 자동 정리 한 번 전체를 되돌린다. 되돌리기도 새 기록이다.
* **무결성 경고:** 저장소 파일이 Gonlith 밖에서 고쳐지면 화면과 검색 결과에 경고가 뜬다. 확인: 로그 변조 7종 중 5종은 재생만으로, 나머지 2종(일관된 재작성, 꼬리 잘라내기)은 저장된 체크포인트와 대조해 검출된다. 사용자 행동은 필요 없다.
  * 정직한 한계: 같은 컴퓨터에서 저장소를 마음대로 고칠 수 있는 프로그램이 일관되게 다시 쓰면 기본 모드로는 못 잡는다. 그것까지 막고 싶은 사람을 위한 것이 보호 모드다(§14.4).
* **진짜 삭제:** 완전 삭제는 내용·솔트·색인·조각·원본 사본을 지운다. 그 뒤 WAL을 비우고 `VACUUM`으로 빈 페이지도 없앤다(S11).

### 13.3 S1 대비 바뀌는 점

* **genesis 키 선택화:** 3판은 `init`이 복구 키를 만들어 출력하고, genesis에 키가 반드시 있어야 했다. 4판은 키 없이 시작한다. 보호 모드를 켤 때 키를 만든다. 형식 판 1은 공개 전이라 바꿀 수 있다 (`docs/format.md` §3.1).
* **자동 init:** 첫 실행 때 저장소가 자동으로 만들어진다. `init` 명령은 남지만 쓸 필요가 없다.
* **항목 종류 추가:** `note`·`document`·`revise`·`archive`·`delete`·합치기 등은 각 단계에서 `docs/format.md`에 추가한다.

## 14. 기본 안전장치 (사용자 행동 없음)

### 14.1 무엇을 막나

* 기억 오염: 웹·문서에 숨은 지시문이 기억으로 들어가 이후 대화에서 실행되는 것. 확인: 연구 보고값은 Sleeper Memory Poisoning 기록률 최대 99.8%, MINJA 주입 98.2% (`docs/research.md` §2.1).
* 실수로 인한 손실.
* 개인정보 유출.

### 14.2 어떻게 (모두 자동)

| 장치 | 동작 |
| :--- | :--- |
| 출처 꼬리표 | 파일·웹·도구 출력에서 온 내용은 `external`로 표시하고, 검색 결과에서 응답마다 새로 만든 무작위 경계로 감싼다. "자료이지 지시가 아님"을 알리는 문구는 설정 파일에 둔다. 경계를 무작위로 하는 이유는 내용에 닫는 경계를 넣어 탈출하는 것을 막기 위함이다 |
| 휴지통 우선 | AI는 휴지통으로만 보낸다. 완전 삭제는 사람만 한다 |
| 되돌리기 | 모든 변경 |
| 자동 쓰기 상한 | 세션당·시간당 AI 저장 수에 상한을 둔다(설정값). 폭주·대량 주입을 막는다 |
| 공간 공개 범위 | §11.3 |
| 웹 수집 제한 | §8.3 |
| 로컬 전용 | 텔레메트리 없음, 화면은 localhost |

* 이 장치들은 확률을 낮출 뿐 완전히 막지는 못한다. 모델이 꼬리표를 무시할 수 있기 때문이다. 확인: MemLineage(arXiv 2605.14421)는 서명·꼬리표만으로는 공격을 막지 못했다고 보고한다.

### 14.3 사용자에게 보이는 것

* 검색 결과·화면에 "웹에서 가져옴", "PDF에서 추출" 같은 출처가 보인다. 관리 정보이기도 하다.
* 문제가 있을 때만 경고한다.

### 14.4 보호 모드 (선택, 기본 꺼짐)

* 원하는 사람만 화면의 "보호 모드"에서 켠다. 켜면 아래가 생긴다:
  * 중요 기억 잠금: 사람 서명으로 확정하고, 바꾸려면 서명이 필요하다
  * 외부 증인: 되돌리기·통째 교체 검출
  * 민감 도구 차단 훅
  * 출처 오염 전파
* 설계 초안은 `docs/protection-mode.md`(3판 보관본)이다. 구현 단계(S12)에서 4판 데이터 모델에 맞춰 다시 설계한다.
* 보장 범위는 그때도 정직하게 둘로 나눈다:
  * MCP로만 접근하는 AI는 막는다
  * 셸 권한 프로그램은 외부 증인을 전제로 탐지만 한다

## 17. 측정 계획

원칙:
* 우리 기기·데이터로 재현한 수치만 기록한다.
* 결과는 `docs/measurements/`에 남긴다.
* 구조상 항상 참인 성질은 회귀 시험으로만 지킨다.
