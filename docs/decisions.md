## 사용자 결정 대기

| # | 질문 | 추천 | 막는 단계 |
| :--- | :--- | :--- | :--- |
| D1 | 해시 체인 기억 8개+와 학술 선행 연구(MemLineage)가 이미 있다. 차별점을 "사람이 서명하고, 읽을 때마다 검증하고, 되돌리면 드러나는 기억 + 일반인 사용성"으로 옮기고, **보장 범위를 둘로 나눠 공개**하는 데 동의하는가? MCP로만 접근하는 에이전트는 막고, 셸 권한 에이전트는 외부 증인·샌드박스를 전제로 탐지만 한다 (`docs/design.md` §3, §4) | 동의 | 공개 소개문 (공개 체크리스트) |

## 1차 재검토 반영 (2026-11-20, 독립 검토 18건, 설계 2판. 절 번호는 2판 기준)

| 지적 | 반영 위치 |
| :--- | :--- |
| 패스키는 "사람이 있었다"만 증명, `localhost` 포트 무관 → 셸 권한 에이전트의 승인 피싱 | §4 보장 범위를 A1/A2로 분리, §6.5 승인문에 항목 수·공간·내용 해시, 승인 감사·빈도 상한, 고정 포트 `origin` 검증 |
| 신뢰 기준이 같은 기기 → 새 키·새 로그로 통째 교체 | §6.6 증인에 원점·genesis·키 지문, 증인 없으면 `approved_local`, 증인을 S4로 당김 |
| 서명 없는 `supersede`·`hide`로 승인 기억 강등 | §6.1·§6.4 승인 기억 변경은 사람 서명 후 효력, 서명 없는 내용 소실은 `broken` |
| 패스키 서명은 C2SP Ed25519가 아님, 검증 규칙 누락, 카운터 | §6.5 `0xff` 확장 유형, 검증 규칙 목록, 카운터 미사용 |
| 오염이 에이전트 `source` 선언에 의존 | §8.5 `gonlith taint` 클라이언트 훅, 사람만 해제, 로그에 기록 |
| 키 수명주기 없음 | §6.7 복구 키·키 등급·철회 의미 |
| 자동 이전 vs 저장 바이트 정본 충돌 | §6.8 로그는 이전하지 않고 판별 형식 공존 |
| 삭제가 실제 삭제가 아님 | §6.9 secure_delete·색인 삭제·WAL·VACUUM·백업·파생 기억 |
| "읽을 때마다 검증" 미정의 | §7.2 재생 기반 상태, `data_version`, 루트 해시 캐시, §7.3 색인 대조, §7.4 복구 흐름 |
| 측정이 구조상 참, 단계 묶음, 근거 없는 상수 | §11 종단 공격 3조건, §13 단계당 기능 1개, §6.3·§6.5 상수 출처 |
| 구조화 출력 미지원 클라이언트, 구획 탈출 | §8.1 텍스트 블록에도 꼬리표, 응답별 무작위 경계 |
| 승인·출처 한 등급에 섞임 | §7.1 등급 3축 |
| 기록 시간 질의 없음 | §8.1·§8.7 `known_at` |
| 화면 Host/Origin, 주소 토큰, 마법사 임의 서버 추가 | §10.2 |
| "인터넷 불필요" 과장 | §5 예외 명시, V1 |
| 동기화 폴더 WAL 손상, `space`는 접근 제어 아님 | §5 |
| 기존 기억 가져오기 | §8.3 |
| 승인 방문 줄이기·승인률 측정 | §8.2, §11 |

| 증분 재생과 루트 캐시 모순 | §7.2 전체 재검증 시점, 증분 재생 가정 명시 |
