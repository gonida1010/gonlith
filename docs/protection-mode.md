# Gonlith 보호 모드 설계 초안 (선택 기능)

> **상태:** 보관된 초안. 2026-11-20 설계 3판 전체를 옮긴 것이다. 2026-11-21 사용자 결정으로 Gonlith의 중심이 "편한 범용 기억·지식 저장소 + 쉬운 관리"로 바뀌었다. 서명 승인·외부 증인·키 수명주기·오염 훅·차단 연결점은 기본 꺼짐인 **보호 모드**로 내려갔다.
> **정본은 [`docs/design.md`](design.md) 4판이다.** 이 문서의 기록 계층·검색·사용성 부분은 4판이 대체한다. 보호 모드를 구현하는 단계(`docs/design.md` §16 S12)에서 이 문서를 출발점으로 다시 설계한다.
> 보류된 결정·가정은 부록 A, 재검토 반영 내역은 부록 B에 있다.

---

## 1. 한 줄 정의

**Gonlith는 AI 에이전트의 장기 기억을 "누가 썼는지, 사람이 승인했는지, 그 뒤로 바뀌지 않았는지" 읽을 때마다 확인해서 돌려주는 로컬 MCP 기억 서버다.**

* 모든 기억은 고칠 수 없는 추가 전용 로그에 남는다. 고치면 새 기록이 옛 기록을 대체한다.
* 사람이 서명한 승인으로만 "승인됨"이 생긴다. 승인된 기억을 바꾸거나 숨기는 것도 사람 서명이 있어야 효력이 생긴다.
* 에이전트가 쓴 기억과 외부 내용에서 온 기억은 출처 꼬리표를 달고 따로 다룬다.
* 어떤 MCP 클라이언트든 연결하면 같은 기억을 공유한다. 계정·API 키가 필요 없다.

## 2. 왜 필요한가

| 과업 | 지금의 한계 | Gonlith가 만들 차이 | 측정 (§11) |
| :--- | :--- | :--- | :--- |
| **기억 오염** | 에이전트 기억은 고칠 수 있는 파일·행이다. 주입된 지시가 기억에 들어가면 이후 세션마다 다시 실행된다. 확인: Sleeper Memory Poisoning (arXiv 2605.15338) 기록률 최대 99.8%; UW Bad Memory (arXiv 2607.14611) Claude Code·Codex 기억 파일 사전 주입이 이후 세션에 지속 | 승인되지 않은 기억을 승인된 것처럼 내보내지 않고, 오염된 세션의 민감 행동을 막을 연결점을 준다 | 실제 모델로 종단 공격 성공률: 꼬리표 없음 / 꼬리표 / 꼬리표+차단 |
| **기억 변조** | 해시 체인 기억 서버들도 키를 서버가 쥐거나, 검증을 검색 경로에서 하지 않는다 (확인, `docs/research.md` §1) | 사람 키 서명 + 읽을 때마다 검증 + 저장소 밖 증인 | 변조 시나리오 검출률 |
| **도구 간 기억 단절** | 제품별 내장 기억은 서로 갇혀 있다 | 여러 클라이언트가 같은 기억을 쓴다 | 클라이언트별 연결 성공 |
| **일반인 사용성** | 기존 기억 서버는 JSON 설정 편집·Docker·API 키를 요구하는 경우가 많다 (판단) | 설치 1줄 + 화면 안내, 기존 기억 가져오기 | 설치→첫 검색 단계 수, 수동 편집 파일 수 |
| **한국어 검색** | SQLite FTS5 trigram은 2글자 한국어 단어를 MATCH로 못 찾는다 (확인, 로컬 실측 `docs/research.md` §4) | 측정으로 정한 한국어 기본값 | 자체 평가셋 Recall@k |
| **바뀌는 사실** | 덮어쓰거나 충돌한 채 남는다 | 유효 시간·기록 시간 분리, 대체 이력 보존 | 시점 질의 정확도 |

**비목표:** 기억 내용이 참인지 판정하지 않는다(서명은 출처와 승인만 보증). 클라이언트 행동을 직접 막지 않는다(연결점만 제공, §8.6). 클라우드 동기화·다중 사용자·호스팅은 첫 범위가 아니다. 추론 엔진(Ollama·vLLM)과 직접 연결하지 않는다(MCP 클라이언트가 아니므로 MCP 지원 호스트를 거친다).

## 3. 차별점과 선행 연구

자세한 비교는 `docs/research.md` §1, §2.

* **해시 체인 기억은 이미 흔하다.** Cognee 출처 원장(기본 꺼짐, HMAC 고정), mnemo(키 없는 체인, 자체 문서가 꼬리 삭제·되돌리기 미검출 인정), kibisis(대칭 HMAC), world-model-mcp(서명 키를 서버가 DB 옆에 보관) 등 최소 8개. 확인.
* **학술 선행 연구:** MemLineage (arXiv 2605.14421, 2026-05-14) — 사용자별 Ed25519 + RFC 6962 Merkle + 파생 계보 + 민감 행동 차단. 배포 제품은 찾지 못함. 확인. 같은 논문에서 **서명만 있는 기준선은 AgentDojo 6개 공격 쌍 모두 실패**. 확인. → 꼬리표를 행동 시점에 강제하는 연결점(§8.6)이 필수다 (판단).
* **Gonlith의 차별점 = 아래 조합 (판단, 함께 갖춘 배포 제품은 찾지 못함):**
  1. 서버 쓰기 경로에는 서명 키가 없다. 승인·승인 기억 변경은 사람이 쥔 키(패스키 또는 사람만 아는 암호)로만.
  2. 검색할 때마다 검증된 상태에서 답한다(§7.3).
  3. 저장소 밖 증인으로 되돌리기·통째 교체를 잡는다(§6.6).
  4. 출처를 쓰기 시점에 묶고, 클라이언트 훅으로 세션 오염을 전파하고, 민감 행동 전에 차단할 수 있다(§8.5, §8.6).
  5. 일반인 사용성: 설치 1줄, 클라이언트 자동 연결, 승인 화면, 기존 기억 가져오기.
  6. 유효 시간·기록 시간 질의, 실제로 지워지는 삭제.
  * 한국어 지원 자체는 Hindsight(Lindera, 선택)·deja-vu(CJK bigram)·basic-memory(한글 n-gram)에도 있어 단독 차별점이 아니다. 확인.
* **소개 문구 방향 (판단):** "tamper-evident"가 아니라 **"사람이 서명하고, 읽을 때마다 검증하고, 되돌리면 드러나는 기억"**. 보장 범위(§4.2)를 소개문에 함께 쓴다.

## 4. 위협 모델과 보장 범위

### 4.1 공격자 등급

보장은 공격자가 **데이터 폴더에 쓸 수 있는가**로 갈린다. 이 구분을 문서·화면·README에서 숨기지 않는다.

| 등급 | 누구 | 예 |
| :--- | :--- | :--- |
| A1 | MCP 도구로만 기억에 접근하는 에이전트 | 채팅 앱의 에이전트, 샌드박스 안 코딩 에이전트(데이터 폴더가 쓰기 허용 범위 밖), 주입문에 조종당한 에이전트 |
| A2 | 같은 사용자 권한의 셸을 가진 에이전트·악성 코드 | 샌드박스 없는 코딩 에이전트, 악성 패키지 |

* 코딩 에이전트의 샌드박스(예: Claude Code·Codex의 파일 쓰기 제한)는 작업 폴더 밖 쓰기를 막는다 (추정, `docs/decisions.md` V6에서 확인). 데이터 폴더를 작업 폴더 밖에 두면 그런 에이전트는 A1이 된다. `gonlith doctor`가 데이터 폴더가 흔한 작업 폴더·동기화 폴더 안에 있으면 경고한다.

### 4.2 공격별 대응과 보장

| # | 공격 | A1 대응 | A2 대응 |
| :--- | :--- | :--- | :--- |
| T1 | 저장소 직접 변조(수정·삽입·삭제·순서) | 해당 없음(쓰기 불가) | Merkle + 서명 승인문으로 **마지막 승인 이전은 검출**. 이후 기록은 원래 미승인 |
| T2 | 정상 쓰기 경로로 주입 (MINJA·Sleeper·Zombie·MemoryGraft) | 에이전트 쓰기는 항상 미승인. 외부 출처면 `external` | 같음 |
| T3 | 세탁 (오염 기억을 읽고 요약해서 다시 씀) | 세션 오염 전파(§8.5) | 같음. 단 훅을 끄면 우회 |
| T4 | 승인 기억 끌어내리기·숨기기 | `supersede`·`hide`가 승인 기억에 효력을 가지려면 사람 서명 필요(§6.4) | 같음 |
| T5 | 되돌리기·통째 교체 (옛 사본, 새 키로 만든 새 로그) | 해당 없음 | **외부 증인이 있을 때만 검출**(§6.6). 증인이 없으면 화면·결과에 "기기 내 승인만"으로 표시 |
| T6 | 승인 피싱 (가짜 승인 화면, 바꿔치기한 `approve` 명령) | 해당 없음(로컬 페이지·프로세스를 띄울 수 없음) | **차단 불가, 탐지만.** 승인문에 항목 수·공간·내용 해시를 넣고, 화면을 열 때마다 최근 승인 감사 목록과 철회 버튼을 보이고, 승인 빈도 상한을 둔다(§6.5) |
| T7 | 승인 피로 (그럴듯한 기억 대량 투입) | 원문·출처·오염 표시, 묶음 크기 상한, 외부 출처 강조 | 같음 |
| T8 | 키 탈취 | 해당 없음 | 암호 키 파일은 복사 후 오프라인 대입 가능 → Argon2id(§6.5). 패스키는 개인키를 내보낼 수 없지만, 동기화 패스키는 기기 밖(패스키 관리자)에 존재한다 |
| T9 | 다른 MCP 서버 도구 설명문 오염 (MCPTox) | 범위 밖. 자체 도구 설명문은 고정·최소화 | 같음 |
| T10 | Gonlith 코드·설정 바꿔치기 | 해당 없음 | 탐지만. 증인에 기록된 승인자 키 지문과 대조 |

**전제:** 공격자는 사람의 생체 인증·암호·복구 단어를 모른다. 운영체제·브라우저는 믿는다. 공격자가 사람을 속여 화면에서 승인하게 만드는 경우(T6·T7)는 기술로 차단하지 못하고, 사후 감사와 철회로 피해를 줄인다.

## 5. 전체 구조

```
 MCP 클라이언트 (Claude Code, Claude Desktop, Cursor, VS Code, Gemini CLI, LM Studio …)
   │ stdio (기본)              │ Streamable HTTP (선택, 로컬 토큰)      │ 클라이언트 훅
   ▼                           ▼                                       ▼ (gonlith taint / gate)
 ┌──────────────────────────── gonlith 서버 ─────────────────────────────┐
 │ MCP 계층: remember / recall / forget, 상태 리소스, instructions          │
 │ 정책 계층: 승인·출처 판정, 세션 오염, 노출 정책, 상한                     │
 │ 검증 상태: 로그 재생으로 만든 메모리 내 상태 (루트 해시 단위 캐시)          │
 │ 검색 계층: 한국어 어휘 색인 + 선택적 벡터 (후보만, 결과는 검증 상태로 판정) │
 │ 기록 계층: 추가 전용 로그 · RFC 6962 Merkle · 체크포인트 · 승인문          │
 │ 저장: SQLite (WAL, secure_delete) — 로그 / 내용 / 파생 색인 분리          │
 └──────────────────────────────────────────────────────────────────────┘
   ▲                                   ▲                         ▲
 웹 화면 (localhost 고정 포트)        CLI (gonlith …)           외부 증인
 상태·승인함·감사·탐색·연결·가져오기   setup·doctor·verify·       (동기화 폴더·git·휴대폰)
   ▲                                  approve·key·export
 패스키 / 암호 키 승인
```

* **단일 저장소, 다중 접속:** 클라이언트마다 stdio 서버 프로세스가 따로 떠도 같은 데이터 폴더를 쓴다. 기록 추가는 `BEGIN IMMEDIATE` 트랜잭션 하나로 직렬화한다 (판단, V3 동시성 시험으로 확인).
* **데이터 폴더:** `platformdirs` 사용자 데이터 폴더, `GONLITH_HOME`으로 변경. iCloud·Dropbox 같은 동기화 폴더 안이면 WAL 손상 위험으로 시작을 거부한다(감지 규칙은 설정 데이터 파일). 이 밖에 쓰는 것은 사용자가 동의한 두 가지뿐이다: 사용자가 고른 증인 위치(§6.6), `gonlith setup`의 클라이언트 설정·훅(백업 후, 정해진 틀로만, §8.6·§10.1).
* **오프라인:** 기본 동작에 네트워크가 필요 없다. 텔레메트리 없음. 예외: 임베딩 모델 내려받기(사용자가 켤 때), 휴대폰 패스키 연동(하이브리드 방식은 인터넷 중계 사용, 확인 필요 V1).
* **`space`는 접근 제어가 아니다.** 기억을 나누는 이름표일 뿐이며, 연결된 모든 클라이언트가 모든 공간을 읽을 수 있다. 공간별 접근 제한이 필요하면 클라이언트별 정책(§8.4)으로 한다.

## 6. 기록과 무결성

### 6.1 로그 항목

* 로그는 정해진 바이트로 직렬화한 항목의 순서열이다. **로그는 절대 다시 쓰지 않는다.** 형식이 바뀌면 새 항목만 새 판 형식을 쓰고, 검증기는 모든 과거 판을 읽는다(§6.9).
* **사람 서명이 실리는 객체는 승인문(`approval`) 하나뿐이다.** 효력을 가지려면 사람 서명이 필요한 동작은 모두 승인문 안의 동작 목록에 들어간다(§6.5). 그래서 모든 서명이 하나의 승인문 체인과 증인 대조 범위 안에 있다.

| 종류 | 뜻 | 쓰는 쪽 | 효력 |
| :--- | :--- | :--- | :--- |
| `genesis` | 로그 시작: 무작위 원점 이름, 형식 판, **최초 신뢰 키 집합(복구 키 공개키와 그 권한)** | `gonlith init` | 위치 0이어야 함 |
| `memory` | 새 기억 | 에이전트(MCP)·사람(화면·CLI) | 즉시 미승인으로 존재 |
| `supersede` | 기존 기억을 새 기억이 대체 | 에이전트·사람 | 대상이 미승인이면 즉시. 승인 기억이면 승인문의 `apply` 동작 후 |
| `hide` | 검색에서 숨김(복구 가능) | 에이전트·사람 | 위와 같음 |
| `redact_request` | 내용 영구 삭제 요청 | 사람(화면·CLI) | 항상 승인문의 `apply` 동작 후 |
| `taint` | 세션 오염 표시 | 훅·서버 | 즉시 |
| `approval` | 서명된 승인문 (§6.5) | 사람 | 서명·정책 검증 후, **효력 위치 = 이 항목의 로그 위치** |

* 기억 `id`는 그 항목의 **잎 위치**(0부터 연속하는 정수)다. 다른 식별자를 두지 않는다.
* `writer=human`은 그 항목이 서명된 승인문의 `approve`·`apply` 대상일 때만 인정한다. 서명 없이 `human`이라 적힌 항목은 미승인 에이전트 기록으로 취급한다.
* 서명된 `redact` 적용 없이 내용이 없으면 `broken`이다.

**`memory` 항목 필드 (W3C PROV 용어 차용):**
* `space`, `category`(기억 분류, 허용 값은 설정 파일), `content_hash` — 항목 종류 `kind`와 구분
* `valid_from`/`valid_to`: 주장값
* `recorded_at`: 참고값. 순서의 정본은 로그 위치다
* `writer`
* `client`: 클라이언트가 밝힌 이름. 검증 안 됨으로 표시한다
* `session`
* `source`: 에이전트가 밝힌 값
* `derived_from`: 에이전트가 밝힌 값 + 세션에서 꺼낸 기억

`origin`(`clean`/`external`)은 저장하지 않고 재생할 때 서버가 계산한다(§8.5).

### 6.2 직렬화와 Merkle

* **바이트 정본:** 항목은 DSSE PAE(타입 문자열 + 길이 + 본문)로 감싼 바이트를 그대로 저장한다. 이 바이트로 RFC 6962 잎 해시 `SHA-256(0x00 ‖ 바이트)`를 만든다. 타입 문자열은 형식 판을 담는다(예: `application/vnd.gonlith.entry.v1+json`). 항목 종류는 본문의 `kind` 필드에 둔다.
* **엄격 판독 규칙** (구현이 달라도 같은 뜻으로 읽히게, 세부는 `docs/format.md`):
  * 본문은 UTF-8 JSON 객체이고 중복 키는 거부한다
  * 숫자는 정수만 허용한다(실수 거부)
  * 종류별 필드 집합이 정확히 일치해야 한다(모르는 필드 거부)
  * 시각은 RFC 3339 UTC(`Z`) 형식이다
  * 본문은 정해진 정규 인코딩(키 정렬, 공백 없음, 비ASCII 그대로)이어야 하고, 다시 인코딩한 결과가 저장 바이트와 다르면 거부한다. 같은 뜻에 바이트 표현이 하나만 있게 하기 위함이다.
* 트리 루트는 RFC 6962 §2.1 정의를 따른다. 확인: 공인 시험 벡터(transparency-dev/merkle)와 재귀 정의 비교 시험 (`docs/research.md` §6). 포함·일관성 증명은 외부 검증기가 필요한 단계(내보내기, S13)에서 구현한다. 로컬 검증은 전체 재생으로 한다.
* SQLite 트리거로 로그 테이블 `UPDATE`·`DELETE`를 거부한다. 실수 방지일 뿐 보안 장치가 아니다.
* 재사용: gon-nexus `orchestrator/event_log.py`의 추가 전용 트리거·`BEGIN IMMEDIATE` 직렬화 방식 (사용자 자산, `~/Projects/gon-nexus`).

### 6.3 내용 분리

* 로그의 `content_hash = SHA-256(salt ‖ 내용 바이트)`. 내용은 **받은 UTF-8 바이트 그대로** 해시하고 정규화하지 않는다(검색용 정규화는 파생 색인에서만).
* `salt`는 항목마다 16바이트 무작위(128비트, NIST SP 800-132 §5.1의 최소 솔트 길이). 내용과 함께 `contents` 테이블에 둔다.
* 내용을 읽을 때마다 해시를 다시 계산한다.

### 6.4 승인 기억의 변경

* 승인 기억을 대상으로 한 `supersede`·`hide`, 그리고 모든 `redact_request`는 "변경 대기"로 쌓인다. 승인문의 `apply` 동작에 들어가야 효력이 생긴다.
* 효력이 생기기 전 `recall`은 승인 기억을 그대로 반환하고 `change_pending` 표시를 붙인다.

### 6.5 승인문

**서명 대상 = C2SP `signed-note` 본문.** 본문은 다음을 담는다.
* 첫 부분: C2SP `tlog-checkpoint` 형식의 체크포인트 (원점 이름, 트리 크기 `N`, 크기 `N`의 루트 해시)
* 이전 승인문 항목의 로그 위치와 잎 해시 (승인문끼리의 체인, 첫 승인문은 genesis를 가리킴)
* **동작 목록**. 모든 대상 위치는 `N` 미만이어야 한다.
  * `approve <위치> <content_hash> <space>`: 기억 승인
  * `revoke <위치>`: 승인 철회
  * `apply <위치>`: 변경 대기 항목(`supersede`·`hide`·`redact_request`)에 효력 부여
  * `key-add <키>`·`key-revoke <키 ID>`: 키 등록·철회 (§6.8)
  * `untaint <세션>`: 세션 오염 해제
* 동작 수 합계

**추가 규칙:**
* `BEGIN IMMEDIATE` 트랜잭션 안에서 "이전 승인문"이 현재 최신 승인문이 아니면 추가를 거부한다. 동시 승인으로 체인이 갈라지지 않게 하기 위함이다. 거부되면 화면·CLI가 새 체크포인트로 다시 서명을 받는다.
* 서명 전에 서버는 로그를 **전체 재검증**한다(§7.2). 변조된 앞부분 위에 사람 서명을 받지 않기 위함이다.
* **에이전트 쓰기에는 서명하지 않는다.** 같은 기기 서버 키는 A2가 읽을 수 있어 가치가 없다. 확인: gon-nexus 실측, macOS 키체인 허용 단위는 실행 파일 (`~/Projects/gon-nexus/docs/knowledge-base/design.md` §4.6).

**승인 수단 (D2):**

| 수단 | 서명 방식 | A2에 대한 한계 | 편의 |
| :--- | :--- | :--- | :--- |
| 패스키 (WebAuthn, `userVerification: required`) — 추천 기본 | ES256 등, `authenticatorData ‖ SHA-256(clientDataJSON)`에 서명. `challenge` = SHA-256(승인문 본문 바이트) | 다른 로컬 페이지가 같은 `localhost` RP로 서명을 요청할 수 있다(포트는 RP ID에 없음). A2는 서버를 내리고 같은 포트를 차지할 수 있다 → T6 탐지만 | Touch ID 한 번 |
| 암호 보호 Ed25519 키 파일 — 대체 수단 | C2SP 표준 Ed25519(`0x01`) | A2가 `approve` 명령을 바꿔 암호를 가로챌 수 있다(T6). 파일을 복사해 오프라인 대입할 수 있다 → Argon2id | 암호 입력, 화면 없는 환경 |

* **암호 키 파일:**
  * Argon2id(RFC 9106 §4 두 번째 권장값: 64 MiB, 반복 3, 병렬 4, 솔트 16바이트) + ChaCha20-Poly1305.
  * 매개변수는 설정 파일이 아니라 **키 파일 머리에 저장**한다. A2가 설정을 바꿔 보호를 약화하지 못하게 하기 위함이다.
  * `cryptography` 50.0.2에서 지원되며, 이 맥에서 키 유도는 32 ms다 (확인, `docs/research.md` §6).
* **패스키 서명:**
  * C2SP signed-note 규격이 미배정 유형용으로 예약한 `0xff` + 고유 식별자로 정의한다. 서명 줄에 `authenticatorData`·`clientDataJSON`·서명을 길이 접두로 함께 담는다 (확인: C2SP `signed-note.md` Signature types).
  * **검증 규칙:**
    * `rpIdHash` = SHA-256(`localhost`)
    * UP·UV 플래그 설정
    * `type` = `webauthn.get`
    * `origin` = **키 등록 동작에 기록된** `http://localhost:<포트>`. 설정 파일이 아니라 서명된 로그에 둔다
    * `challenge` = SHA-256(승인문 본문 바이트)
    * 서명 카운터는 쓰지 않는다. 동기화 패스키는 항상 0이다
  * 바이트 단위 정의(본문 끝 줄바꿈 포함 여부, 키 이름, 키 ID)는 `docs/format.md`에 둔다.
* **승인 감사 (T6 완화):** 화면을 열 때마다 아래 내용과 철회 버튼을 보여 준다. 승인 빈도 상한은 설정값이다.
  * 최근 승인문 목록
  * 각 승인문의 동작 목록, 시각, 키

### 6.6 외부 증인

* **증인 기록 =** 최신 승인문 바이트 그대로(체크포인트 포함) + genesis 잎 해시 + 그 시점 키 집합 지문(키 공개키 목록의 해시). 기억 내용은 들어가지 않는다.
* **대조 규칙** (`gonlith verify`) — 아래 넷 중 하나라도 어긋나면 이상:
  1. 로그 위치 0의 잎 해시 = 증인의 genesis 해시
  2. 로그의 크기 `N` 루트 = 증인 승인문의 체크포인트 루트 (로컬은 전체 로그가 있으므로 루트를 직접 다시 계산한다)
  3. 증인 승인문 바이트가 로그의 위치 `N` 이상 어딘가에 승인문 항목으로 존재
  4. 재생으로 얻은 그 승인문 시점의 키 집합 지문 = 증인 지문
* **"증인이 확인한 승인"** = 로그 위치 < 증인 승인문의 트리 크기 `N`인 승인.
* **위치:** 사용자가 고른 데이터 폴더 밖 장소. 동기화 폴더의 작은 텍스트 파일, git 원격 저장소, 휴대폰(QR) 등이다. A2가 쓸 수 없는 곳일수록 보장이 강하다. 같은 기기의 일반 폴더면 약하다고 화면에 표시한다.
* 설치 마법사의 기본 단계로 둔다(D7). 건너뛰면 모든 승인이 `approved_local`이다.
* 공개 투명성 로그(Sigstore Rekor)에 승인문 해시만 올리는 방법은 후순위 선택지다 (`docs/research.md` §3).

### 6.7 신뢰 시작점

* `gonlith init`은 아래 순서로 동작한다:
  1. 복구 키(Ed25519)를 만든다
  2. 그 공개키와 권한을 genesis에 넣는다
  3. 개인키는 사람이 적어 둘 형태로 **한 번만** 보여 주고 저장하지 않는다
* 증인을 등록하면 genesis 해시가 증인에 들어간다.
* 따라서 모든 신뢰는 genesis의 복구 키 → 승인문의 `key-add` → 승인 키의 `approve` 순서로 서명된 로그 안에서만 이어진다. 설정 파일은 신뢰 판단에 쓰지 않는다.
* 공개 전에 만든 시험 로그는 형식 확정 전 것이므로 버린다. 공개 판부터 형식 판 1을 고정한다.

### 6.8 키 수명주기

* **키 권한은 서명된 로그 안에 둔다.** `key-add` 동작이 키의 공개키, 종류(`ed25519` / `webauthn`과 고정 `origin`), 권한 집합을 담는다. 설정 파일로는 바꿀 수 없다.
* **권한 (기본안):**

| 권한 | 복구 키 | 승인 키 (패스키·암호) |
| :--- | :--- | :--- |
| `key-add`·`key-revoke` | O | X |
| `approve`·`revoke`·체크포인트 | X | O |
| `apply`(변경·삭제)·`untaint` | X | `key-add` 때 `strong` 권한을 받은 키만 (추천: 패스키) |

  * 복구 키는 키 관리만 한다. 그래서 일상적으로 꺼낼 일이 없다.
  * 약한 암호 키가 털려도 패스키를 지우거나 내용을 지울 수 없다.
* **한 승인문에는 한 키의 서명만 붙는다.** 그 승인문의 모든 동작이 그 키 권한 안에 있어야 한다. 키 관리는 복구 키로 서명한 별도 승인문으로 한다.
* **철회 의미:** 철회된 키의 승인은 "증인이 확인한 승인"(§6.6)이면 유효하다. 아니면 무효이며, 다시 승인해야 한다.
* 모든 승인 키와 복구 키를 잃으면 새 로그를 만들고, 기존 기억을 "가져오기"(§8.3)로 다시 승인한다. 옛 로그는 읽기 전용으로 보존한다.

### 6.9 형식 판과 업그레이드

* 로그는 이전하지 않는다. 파생 테이블(색인·벡터·캐시)만 업그레이드 때 재구축한다.
* 업그레이드 전 데이터 폴더를 백업하고, 백업은 진짜 삭제(§6.10) 대상에 포함한다.

### 6.10 진짜 삭제

`redact_request`가 서명된 `apply`로 효력을 가지면 다음을 수행한다.
1. `contents`의 내용·솔트를 지운다. `PRAGMA secure_delete=ON`은 상시 켜 둔다.
2. 어휘 색인·벡터에서 지운다.
3. WAL 체크포인트(`TRUNCATE`) 후 `VACUUM`으로 빈 페이지를 없앤다.
4. Gonlith가 만든 백업·내보내기 목록을 보여 주고 함께 지울지 묻는다. 사용자가 밖으로 복사한 사본은 지울 수 없다고 안내한다.
5. `derived_from`으로 이 기억을 참고한 기억을 화면에 표시해 함께 검토하게 한다.

로그와 Merkle 트리는 그대로라 무결성 검증은 계속 된다. 솔트도 함께 지워지므로 짧은 내용을 해시에서 추측할 수 없다 (판단).

## 7. 검증된 상태

### 7.1 등급은 세 축 + 표시 1개

| 축 | 값 | 뜻 |
| :--- | :--- | :--- |
| 승인 (`approval`) | `approved` / `approved_local` / `unapproved` | `approved_local` = 증인이 없거나 증인이 아직 확인하지 않은 승인 |
| 출처 (`origin`) | `clean` / `external` | §8.5 |
| 무결성 (`integrity`) | `ok` / `broken` | `broken`이면 내용을 내보내지 않고 경고만 |
| 표시 (`change_pending`) | 참/거짓 | 서명 대기 중인 변경이 있음 (§6.4) |

* 축들은 서로 독립이다. 예를 들어 웹에서 온 내용을 사람이 승인하면 `approved` + `external`이 된다.

### 7.2 계산 방식

* **전체 재검증:** 로그를 처음부터 재생해 메모리 안에 검증된 상태를 만든다. 재생 중 확인하는 것:
  * 엄격 판독
  * 잎 해시·루트
  * 내용 해시
  * 승인문 서명·권한·체인·대상 위치
  * 증인 대조
* **전체 재검증 시점:**
  * 서버 시작
  * `gonlith verify`
  * 승인문 서명 직전
  * 설정된 주기
* **증분 재생:** `PRAGMA data_version`이 바뀌면 다음을 수행한다:
  1. 마지막으로 검증한 위치의 잎 해시가 그대로인지 확인
  2. 새 항목만 이어서 재생
* **증분 재생의 가정:** 앞부분이 바뀌지 않았다고 가정한다. 다른 프로세스가 앞쪽 행을 제자리에서 고치면 다음 전체 재검증 때 드러난다. 이 간격(주기)이 탐지 지연의 상한이다.
* 포함 증명만으로는 "철회·숨김된 적 없음"을 증명할 수 없어서 전체 재생 방식을 택했다.
* 비용은 기억 1만·10만 건에서 측정한다(§11).

### 7.3 검색 시 검증

* 색인은 후보를 찾을 뿐이다. 후보마다 검증된 상태에서 등급을 가져오고, 내용 해시를 다시 확인한다.
* 시작할 때 색인과 검증된 상태를 대조한다. 누락·여분이 있으면 색인을 다시 만든다. 색인이 승인 기억을 조용히 빼먹는 공격을 막기 위함이다.

### 7.4 무결성 실패 시 복구 흐름

한 바이트만 깨져도 그 위치 이후의 판단이 모두 의심 상태가 된다. 그래서 실패 시 화면과 `gonlith doctor`가 아래를 안내한다.
* 깨진 위치
* 마지막으로 정상 검증된 승인문
* 증인과 일치하는 백업 찾기
* 복원 후 재검증

복원은 사람이 실행한다.

## 8. 동작 규칙

### 8.1 MCP 도구 (3개)

| 도구 | 입력 | 출력 |
| :--- | :--- | :--- |
| `remember` | `content`, `category?`, `space?`, `valid_from?`, `valid_to?`, `supersedes?`, `source?`, `derived_from?` | `id`, `approval`, `origin`, 승인 대기 수 |
| `recall` | `query`, `space?`, `valid_at?`(그 시점에 참이던 것), `known_at?`(그 시점까지 기록된 것), `include?`, `limit?` | 항목별 내용·등급 세 축과 `change_pending`·유효 시간·기록 위치·출처·일치 이유, 경고 |
| `forget` | `id`, `reason` | 미승인이면 숨김, 승인 기억이면 변경 대기 |

* **승인·삭제·키·오염 해제는 MCP로 노출하지 않는다.**
* **호환성:** `structuredContent`·리소스·`instructions`를 무시하는 클라이언트가 많다(재검토 지적, 클라이언트별 확인 V4). 그래서 아래 내용을 **텍스트 내용 블록에도 같이** 넣는다:
  * 등급 꼬리표
  * 승인 대기 수
  * 경고
* **데이터 구획:** 미승인·외부 내용은 응답마다 새로 만든 무작위 경계 문자열로 감싼다. 내용에 닫는 구획 문자열을 넣어 탈출하는 것을 막기 위해서다. 구획 문구는 설정 파일에 둔다.
* **규격:** 공식 `mcp` SDK 2.x는 2026-07-28(무상태)과 2025-11-25 클라이언트를 모두 지원한다고 밝힌다. 확인 (`docs/research.md` §2.4). Roots는 폐지 예정이라 쓰지 않고, `space` 인자와 환경변수 `GONLITH_SPACE`로 공간을 정한다.
* **리소스:** `gonlith://status`, `gonlith://memory/{id}`. 서버 `instructions` 문구는 설정 파일에 둔다.

### 8.2 승인 흐름

1. 에이전트가 `remember` → 승인 대기함. 응답 텍스트에 "승인 대기 N건, 화면 주소"를 넣는다.
2. 클라이언트가 MCP 요청 단계 URL 모드(elicitation)를 지원하면 승인 화면 열기를 제안한다 (지원 여부 V7). 방문 횟수를 줄이기 위함이다.
3. 화면에는 각 항목의 아래 정보가 보인다. 외부 출처는 경고색으로 표시한다.
   * 원문
   * 출처
   * 오염 표시
   * 쓴 클라이언트
   * 참고한 기억
4. 고른 뒤 승인 → 패스키(또는 CLI 암호) → 승인문 서명 → 증인 갱신.
5. 승인률·대기 적체를 측정한다(§11). 아무도 승인하지 않으면 신뢰 모델이 비어 버리기 때문이다.

### 8.3 기존 기억 가져오기 (온보딩 + 사전 주입 대응)

* 아래 기존 기억을 **미승인 항목으로** 가져와 승인함에서 검토하게 한다. 출처는 `file`이고 원본 경로를 기록한다.
  * 프로젝트 `CLAUDE.md`·`AGENTS.md`
  * Claude Code 자동 기억 파일
  * 공식 MCP memory 서버 JSONL
* 사전 주입된 기억 파일(Bad Memory 경로 b)을 사람이 한 번 검토하는 계기가 된다.
* 지원 형식·경로는 설정 데이터 파일로 관리한다.

### 8.4 검색 노출 정책 (D3)

* 추천 기본값:
  * `approved*` + `unapproved`는 반환하고, `external`은 명시 요청 시만 반환
  * 모든 항목에 꼬리표를 붙이고, 미승인은 데이터 구획으로 감싼다
* 엄격 모드: `approved`만 반환.
* 공간별·클라이언트별로 설정 파일에서 정한다.

### 8.5 출처와 세션 오염

* `origin = external`이 되는 경우:
  * `source`가 `web`·`tool_output`·`file`이거나, 생략(`unknown`)인데 설정이 `unknown`을 외부로 취급할 때(추천 기본)
  * 그 세션이 이미 오염되었을 때
* 세션은 아래 두 경로로 오염된다:
  * 그 세션에서 `external` 기억을 꺼냈다
  * **클라이언트 훅이 알렸다:** `gonlith taint` 명령을 클라이언트의 도구 사용 후 훅(예: Claude Code `PostToolUse`)에 걸어, 웹·파일 읽기 같은 외부 도구를 쓰면 세션을 오염으로 표시한다. 에이전트가 `source="conversation"`이라고 거짓으로 밝히는 주된 주입 경로를 막기 위함이다. 어떤 도구를 외부로 볼지는 설정 데이터 파일로 정한다.
* 오염 해제는 승인문의 `untaint` 동작으로만 한다(§6.5). 서버가 재시작해도 오염 상태는 로그에 남는다(`taint` 항목).
* **세션 경계:**
  * stdio: 서버 프로세스 1개 = 세션 1개
  * 한 프로세스가 여러 대화를 담는 클라이언트(Claude Desktop 추정, V8)는 대화 사이에 오염이 번진다. 안전한 쪽으로 틀리는 것이며, 불편은 측정한다
  * HTTP: 클라이언트 접속 토큰 1개 = 세션 1개 (SDK 지원 확인 V2)
* 한계: 사용자가 대화창에 붙여 넣은 외부 글은 서버가 알 수 없다. 훅도 없는 클라이언트에서는 에이전트의 `source` 선언에 의존한다. 이 차이를 클라이언트별 호환표에 적는다.

### 8.6 민감 행동 차단 연결점

* `gonlith gate`: 현재 세션이 오염되었는지, 미승인 기억을 꺼냈는지를 종료 코드로 알려 준다.
* 클라이언트의 도구 사용 전 훅(예: Claude Code `PreToolUse`)에서 셸·외부 전송 같은 민감 도구 앞에 건다. 민감 도구 목록은 설정 데이터 파일로 정한다.
* `setup`이 지원 클라이언트에 `taint`·`gate` 훅을 함께 설치한다(사용자 동의, V4·V9).
* MemLineage 결과(서명만으로는 실패)에 대한 우리 쪽 대응이다. 효과는 §11 종단 측정으로 확인한다.

### 8.7 유효 시간과 대체

* `supersede`는 옛 기억의 `valid_to`를 새 기억의 `valid_from`으로 닫는다. 옛 기억은 남긴다(Zep/Graphiti 방식, 확인 arXiv 2501.13956).
* `valid_at`은 그 시점에 참이던 기억을 찾는다. `known_at`은 그 시점까지 로그에 있던 것만 보는 질의다(로그 위치 기준).
* 의미가 겹치는 기억(벡터 단계 이후)은 화면에 "충돌 후보"로 보인다. 사람이 대체할지 병존시킬지 고르고, 자동 병합은 하지 않는다.

### 8.8 상한과 상수

* 아래 값은 모두 설정 파일 값이다:
  * 자동 쓰기 상한(세션당·하루당)
  * 내용 최대 길이
  * 결과 수
  * 승인 묶음 크기
  * 승인 빈도
  * 웹 포트(설치 때 빈 포트를 골라 고정)
  * Argon2id 매개변수
* 기본값마다 출처(RFC·문서·측정)를 설정 파일 옆 문서에 적는다. 출처 없는 상수는 두지 않는다.
* 상한을 넘는 쓰기는 거부하고 이유를 돌려준다.

## 9. 검색 (한국어 포함)

* **1단계 (기본, 내려받기 없음):** SQLite FTS5. trigram 단독은 2글자 단어를 못 찾아 기본값이 될 수 없다(확인). 아래 후보를 자체 평가셋으로 측정해 고른다:
  * (a) `kiwipiepy` 형태소
  * (b) 문자 2-gram
  * (c) 둘의 혼합
* **2단계 (선택):** 임베딩 + 1단계 점수 결합.
  * 저장: `sqlite-vec`, 또는 개인 규모라면 메모리 내 전수 비교
  * 실행: ONNX 계열(`fastembed`·`model2vec`)을 PyTorch보다 우선 측정
  * 모델은 설정 파일로 고른다
  * gon-nexus의 이전 측정(법률 검색 데이터, KURE-v2 R@1 84.0 vs BM25 혼합 77.7)은 다른 도메인이라 근거로 쓰지 않는다
* **평가셋:** 회사 데이터 없이 직접 만든 한국어·영어 기억 질의 쌍. 표본은 시드를 고정한다. 공개 여부는 D6.

### 10.1 설치와 연결 — 걸림 없이

| 단계 | 일반인 | 개발자 |
| :--- | :--- | :--- |
| 설치 | 안내 페이지 명령 1줄(`uv` 기반) 또는 Claude Desktop 확장 묶음(MCPB, V5) | `uvx gonlith` / `uv tool install gonlith` |

| 증인 | 위치 고르기(동기화 폴더·git·QR) 또는 건너뛰기(기기 내 승인만) | `gonlith witness add` |
| 연결 | 설치된 MCP 클라이언트 자동 탐지 → 체크 → 백업 후 정해진 틀로 추가, 바뀌는 내용 미리 보기, 훅 설치 여부 선택 | `gonlith setup --client <이름>` 또는 설정 조각 출력 |

**걸림을 없애는 규칙 (판단):**
* 시작이 빨라야 한다. 임베딩은 처음 쓸 때 불러오고, 시작 시간(로그 재생 포함)을 측정한다.
* 클라이언트 설정에는 실행 파일을 절대 경로로 쓴다. `PATH` 차이를 피하기 위함이다.
* 동시 쓰기 대기 시간은 설정값으로 둔다.
* `stdout`에는 MCP 메시지만 쓴다. 로그는 파일과 `stderr`로 보낸다.
* 아래 내용은 코드가 아니라 **출처 링크·확인 날짜가 붙은 설정 데이터 파일**로 관리한다. 자주 바뀌기 때문이다:
  * 클라이언트 설정 파일 위치·형식
  * 훅 지원 여부
  * 외부 도구·민감 도구 목록
* 클라이언트별 호환표(연결·구조화 출력·훅·요청 단계 지원)를 문서로 공개한다. "완벽 호환" 같은 표현은 쓰지 않는다.

### 10.2 웹 화면

* `127.0.0.1`에만 묶는다. 요청마다 `Host`·`Origin` 헤더를 검사한다. DNS 리바인딩·CSRF를 막기 위함이다.
* 접속 토큰은 일회용 주소로 한 번 넘긴 뒤 쿠키로 바꾼다. 주소에 남은 토큰이 브라우저 기록에 새지 않게 하기 위함이다.
* 패스키 RP ID는 `localhost`로, 접속 주소는 고정 포트의 `http://localhost:<포트>`로 한다. `127.0.0.1`은 RP ID로 쓸 수 없다고 알려져 있다 (V1에서 확인).
* **화면:**
  * 홈: 기억 수, 승인 대기, 무결성·증인 상태를 쉬운 말로
  * 승인함
  * 승인 감사: 최근 승인 목록과 철회
  * 기억 탐색: 검색, 공간, 타임라인, 등급 필터, "왜 나왔나", "어디서 왔나"
  * 연결된 앱
  * 가져오기
  * 백업·내보내기
  * 설정
* 화면은 클라이언트 설정에 정해진 틀만 쓸 수 있다. 화면을 이용해 임의의 MCP 서버를 추가하지 못하게 하기 위함이다.
* 문구는 언어 파일(한국어·영어)로 둔다. 기술은 Starlette + 빌드 단계 없는 정적 HTML·JS다 (판단).

### 10.3 내보내기

* 검증 가능한 묶음: 로그 바이트, 승인문, 키, 증인 기록, 남은 내용. 별도 검증기로 확인할 수 있게 `docs/format.md`에 형식을 공개한다.
* 사람이 읽는 Markdown 내보내기도 준다(검증용 아님).
